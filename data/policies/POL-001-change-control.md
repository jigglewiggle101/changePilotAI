# POL-001: Change Control Standard
Status: Synthetic example policy for the ChangePilot AI portfolio. Not an actual company policy.

## Purpose
Changes to business-critical services must be planned, assessed, reviewed, tested and documented before implementation.

## Required evidence
- Defined scope and target services.
- Named accountable owner and affected teams.
- Impact assessment covering upstream and downstream dependencies.
- Test plan and acceptance criteria.
- Rollback or recovery plan appropriate to the change.
- Required security review where access, identity, sensitive data or security controls are affected.
- Monitoring and post-change verification plan.

## Review rules
A missing mandatory item must be reported as a gap. The assistant must not mark a change as approved or ready solely because an LLM says it is safe. Approval is performed by an authorised human reviewer.

## Source note
This fictional policy is informed by general configuration/change-management concepts. See NIST SP 800-128: https://csrc.nist.gov/pubs/sp/800/128/r1/final
